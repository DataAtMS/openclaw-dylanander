§01 · The single-agent ceiling

One agent isn't an operating system.

A single-agent assistant is great for a side project. Try running four businesses through it and the seams show inside a week. Same four failure modes, every time.

Failure 01

Cross-contamination

The ecom brand's voice leaks into the agency's client email. The portfolio company's confidential data shows up in a newsletter draft. One agent, one memory, four businesses, zero firewall.

Failure 02

Priority collapse

Everything is P0 because nothing is. The agent surfaces a Slack ping with the same urgency as a $24K renewal. Without explicit lanes, the agent treats every message as a tap on the shoulder.

Failure 03

Channel chaos

The agent doesn't know that Telegram is mobile-direct, Slack is team-facing, and email goes from Steve the EA, never from the principal. Without per-channel rules, everything sounds like Slack.

Failure 04

No org chart

The agent does brilliant first-pass strategy and brilliant first-pass copy and brilliant first-pass code review. None of it ships, because there's no specialist sub-agent that owns the output and no protocol for handing the work off.

§02 · What changes with the kit

Same model. Same workspace. An actual org chart.

The kit gives your OpenClaw the scaffold that distinguishes a clever assistant from an actual operations layer. Multi-agent registry. Iron-law memory. Priority lanes with weekday SLAs. Per-channel rules. Business-prefix shorthand.

Fix 01

Per-business memory firewall

Every thread, every memory, every task is tagged with a business prefix (MS, JB, HM, DA, LTM). The agent reasons inside one lane at a time. No accidental leak from agency context into ecom output.

Fix 02

Priority lanes that mean something

P0 has a 48-hour weekday SLA. Day 2 nudges. Day 3 auto-demotes to P1 unless re-committed. Most threads die at P1 or P2. Closing is the win.

Fix 03

Specialist sub-agents

Main EA. Content writer. Brand ops agent. Each with its own SOUL, its own memory namespace, its own toolkit, its own iron laws. The main agent delegates; specialists own their lane.

Fix 04

Channels treated as channels

Telegram is mobile-direct. Slack is team-facing. Email is draft-and-approve, sent from the EA, never the principal. The agent stops sounding like Slack everywhere.

§05 · Install

Three modes. Safe by default.

The default install never touches your existing SOUL, USER, AGENTS, or MEMORY files. Everything lands in a new dylan-ander-openclaw/ subfolder. Your agent reads it and proposes patterns to adopt with your approval.

Mode: Learn (default)

Read-only. Safe for any existing workspace.

Downloads the full kit into dylan-ander-openclaw/. Your workspace root is never modified. Tell your agent to read the architecture doc, then propose patterns to adopt one at a time.

curl -sSL https://openclaw.dylanander.com/install.sh | bash
Mode: Additive

Learn mode plus optional scaffolding.

Same as Learn, plus creates empty optional directories: memory/archive/, journal/, threads/, brain/people/, brain/companies/.

curl -sSL https://openclaw.dylanander.com/install.sh | bash -s -- --mode=additive
Mode: Fresh

Brand-new workspace only.

Writes full templates to the workspace root. If you already have SOUL.md or MEMORY.md, they're preserved and new versions land alongside with a .new suffix for manual diff.

curl -sSL https://openclaw.dylanander.com/install.sh | bash -s -- --mode=fresh
Or: tell the agent

Skip the terminal entirely.

Paste this into any OpenClaw chat. The agent reads the architecture doc first, then walks the rest of the kit before proposing anything.

§06 · Honest answers

Real questions.

Will this overwrite my existing SOUL, USER, AGENTS, or MEMORY files?

No. The default install mode (Learn) puts everything into a new dylan-ander-openclaw/ subfolder. Your workspace root stays exactly as you left it. Templates land as *.example.md so it's obvious they're reference material. Fresh mode preserves existing files and lands new versions alongside with a .new suffix.

Is this safe to run? It's a third-party install.

Three reasons. MIT license, open source, you can read the install script before running. It's under 250 lines of shell. The default mode is read-only. The GitHub repo has full commit history.

How is this different from Nik Sharma's Operator Kit?

Nik's kit is the discipline layer for one agent. This kit is the multi-agent OS on top. Nik teaches your agent how to think; this kit gives you the org chart, the SLA system, the multi-channel wiring, and the migration story from a single-agent tool. Stack them. They're not competing products.

Do I need to run four businesses to use this?

No. The patterns scale down. The threads system, iron-law memory format, and business-prefix shorthand all work for one business with multiple projects. The multi-agent registry works if you only run a main agent. Use what fits, ignore the rest.

What's actually in the kit?

Eight markdown templates at the root (AGENTS, SOUL, IDENTITY, USER, MEMORY, TOOLS, HEARTBEAT, plus README). A threads protocol. A memory and journal scaffold. A multi-agent registry. A skills folder. Three architecture docs. One safe installer. No skills, no executables, no daemons.

What OpenClaw version do I need?

Any modern version. The kit is plain markdown plus a shell script. Zero dependency on specific OpenClaw releases.
